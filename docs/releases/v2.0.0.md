# Takosumi v2.0.0

Takosumi is an AGPL-3.0-only, provider-neutral Git/OpenTofu control plane. This is a source/module software release for operators composing their own instance.

## Highlights

- App-scoped ownership, access and Interface delegation, with retained compatibility for existing stored data.
- Reviewed app Git updates from the CLI, explicit Plan/Apply, and retained install-attempt keys for manual recovery after a lost response.
- Run/Runner recovery, source-archive custody, scoped backups, and preservation of generated secrets across app updates.
- Account notifications, sign-in and dashboard improvements, and stronger credential redaction and Runner isolation.

## Upgrade notes

This is a major release. Read the [v2.0.0 CHANGELOG](https://github.com/tako0614/takosumi/blob/v2.0.0/CHANGELOG.md) and [release/upgrade runbook](https://github.com/tako0614/takosumi/blob/v2.0.0/docs/operations/takosumi-v1-release.md) before updating an existing instance.

- `DELETE /api/v1/capsules/{id}` now schedules uninstall with a default seven-day grace period and returns `{capsule, graceDays}`. It previously returned a manual destroy Plan. Migrate callers before upgrading; the documented manual destroy-plan and cancel-uninstall routes remain available.
- Workspace extension and Interface routes now restrict browser sessions and unbound personal access tokens to the Workspace owner. App users must use the app-scoped routes and their app roles.
- The built-in backup API is a partial ledger export, not a complete backup or importer. Scheduled uninstall can continue when its pre-destroy export fails. Operators must provide and verify their own database/object-store backup and restore procedure.
- Back up persistent data and review pending migrations. Compose migration execution is forward-only; reverting a runtime does not revert its database.
- Drain old execution contexts before accepting new app-authorized uninstall reservations. Do not mix incompatible readers or roll back to an old runtime while new-mode reservations or generated-secret changes remain pending; follow the documented forward-repair procedure.
- Keep existing object-storage references and encrypted inputs unchanged. Publishing this source release does not migrate any instance.

## Distribution and scope

Use the signed `v2.0.0` Git tag or GitHub's source archive. The pinned local quickstart builds its Runner from that checkout. Operators remain responsible for choosing and qualifying their runtime, storage and executor configuration.

This release does not publish an npm service, OCI Runner image, desktop/mobile app, or Hosted service deployment. Cloudflare self-host Apply/Destroy still requires its separately qualified digest authorities, and the Bun/PostgreSQL reference composition requires a separately integrated Runner. Hosted availability, billing, credentials and service guarantees are separate from this OSS release.
