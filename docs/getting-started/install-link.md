# 追加リンクを配る

README やウェブサイトに追加リンクを置くと、読んだ人は Takosumi の追加画面を、取得元が
入った状態で開けます。リンクが行うのは入力までです。**開いただけでは何も作られません。**
追加する人が画面で内容を確かめ、自分で **追加** を押します。

リポジトリは先に[追加できるリポジトリを用意する](./prepare-repository.md)の形にしておきます。

## リンクの形

```text
https://<Takosumi の origin>/install?git=<Git の URL>&ref=<ブランチ・タグ・commit>&path=<module のフォルダ>
```

`<Takosumi の origin>` は、追加してもらう先の Takosumi の dashboard の origin（`https://` から
ホスト名までの部分）です。公式の hosted service では `https://app.takosumi.com`、自分で運用している
Takosumi ではその origin です。

README に置くときは、Markdown のリンクにします。

```markdown
[Takosumi で追加](https://takosumi.example.com/install?git=https://github.com/acme/notes.git&ref=v1.2.0&path=deploy/opentofu)
```

origin、リポジトリ、版、フォルダは自分のものに置き換えます。

値に `&`、`+`、`#`、`%`、空白が入るときは、その値を URL エンコードします。たとえば `+` は
`%2B` と書きます。`+` をそのまま書くと空白として読まれます。

## パラメータ

| パラメータ | 意味 |
| --- | --- |
| `git` | module（OpenTofu の設定を置いたフォルダ）がある Git リポジトリの URL。`https://` で始まり、ユーザー名、パスワード、`?` 以降の query、`#` 以降の fragment を含まないもの |
| `ref` | 追加する版。ブランチ、タグ、commit のどれか。省略すると既定のブランチ |
| `path` | 追加する module のフォルダ。省略すると Takosumi が調べて決めます |
| `sourcePath` | Takosumi が取得して調べる、リポジトリの中のフォルダ。省略するとリポジトリ全体（`.`） |
| `name` | サービス名。半角小文字、数字、ハイフンだけ。省略するとリポジトリ名 |
| `source` | `git`、`ref`、`path` を 1 つにまとめた形（下の「1 つにまとめた形」） |
| `product`、`return_uri` | 追加のあと、自分のアプリへ戻すときに組で使います（[App Handoff](../reference/app-handoff.md)） |

`git` か `source` のどちらか 1 つを必ず付けます。ほかは任意です。module の変数の値は
リンクでは渡せません。追加する人が **サービスを設定** の画面で入れます。

リポジトリ名に半角小文字、数字、ハイフン以外の文字（大文字、`_`、`.` など）が入っているときは、
`name` を付けます。リポジトリ名のままだと、
**追加** を押したときに「サービス名は半角小文字・数字・ハイフンで入力してください。」と表示され、
追加する人が名前を直す必要があります。

### 版の選び方

追加するとき、Takosumi は `ref` をその時点の commit に固定します。そのあとの動きは `ref` の
種類で変わります。

- **ブランチ**（`main` など）: 追加したサービスはそのブランチを追跡します。新しい commit が
  入ると **更新があります** になります。
- **タグか commit**（`v1.2.0` など）: その版のままです。新しい版へは、追加した人が
  **バージョンを変更** で切り替えます（[新しい版に更新する](./after-adding.md#新しい版に更新する)）。
  ただし、タグを別の commit に付け直すと、ブランチと同じように **更新があります** になります。

### `path` と `sourcePath`

`path` は **`sourcePath` からの相対パス**です。リポジトリの最上位からではありません。

| module の場所 | 書き方 |
| --- | --- |
| リポジトリの `deploy/opentofu` | `path=deploy/opentofu` |
| リポジトリの `infra/deploy/opentofu` で、`infra` の中だけを調べさせる | `sourcePath=infra&path=deploy/opentofu` |
| リポジトリの最上位 | `path=.` |

`sourcePath` は、テスト用や例の module が同じリポジトリにあって、調べる範囲を本体の module に
絞りたいときに使います（[追加できなくなるもの](./prepare-repository.md#追加できなくなるもの)）。

フォルダは `deploy/opentofu` のように書きます。`/` や `./` で始まるもの、`/` で終わるもの、
空の区切り（`a//b`）、`.` や `..` の区切り、`\`、ドライブ名（`C:`）を含むもの、1,024 文字を
超えるものは使えません。

Takosumi は、追加する人が **追加** を押したあとにリポジトリを調べ、`path` をその結果と照らし
合わせます。

- `path` が見つかり、module が 1 つだけのとき: その module を使います。
- `path` が見つかり、module が複数あるとき: その module を選んだ状態で **モジュールを選択** が
  開きます。追加する人は別の module も選べます。
- `path` が見つからないとき: `path` は使われず、調べた結果で決めます。module が 1 つなら
  それを使い、複数なら追加する人が選びます。1 つも無ければ「このリポジトリ版には追加できる
  モジュールがありません。」と表示されます。`path` を使わなかったことは表示されないため、
  書き違い（とくに `sourcePath` を付けたのにリポジトリの最上位から書いたパス）に気づきにくく
  なります。

### 1 つにまとめた形

`source` には、OpenTofu の module の住所と同じ形で書きます。

```text
https://takosumi.example.com/install?source=git::https://github.com/acme/notes.git//deploy/opentofu?ref=v1.2.0
```

`//` の後ろが module のフォルダ、`?` の後ろが版です。どちらも省けます。`?` の後ろには `ref`
だけを書けます。`git` と一緒には使えません。`ref` と `path` は、`source` の中と外のどちらか
一方に書きます。`sourcePath` は `source` と一緒に使えます。

## 開いた人の Takosumi で開くリンク

追加してもらう Takosumi の origin が決まっているなら、上の origin つきのリンクを使います。
どの Takosumi を使う人にも配りたいときは、origin を決めずに、リンクを開いた人が使っている
Takosumi で開くリンクにできます。`https://<Takosumi の origin>/install` の代わりに
`web+takosumi:install` を使います。パラメータと規則は同じで、読めないときに開く画面だけが
違います（下の「リンクが使われないとき」）。

```text
web+takosumi:install?git=https://github.com/acme/notes.git&ref=v1.2.0&path=deploy/opentofu
```

このリンクが開くのは、開いた人がブラウザに登録した Takosumi です。登録は、その Takosumi の
dashboard の **アカウント** にある **ストアからの追加先** で **この端末を登録** を押し、
ブラウザの確認に応じます。

- 登録していないブラウザでは、このリンクは開けません。
- 登録に対応していないブラウザでは、**アカウント** に「このブラウザはこの機能に未対応です。」と
  表示されます。
- GitHub の README のように、`https:` などの決まった形以外のリンクを取り除く表示先では、
  リンクとして働かないことがあります。

README には、origin つきのリンクと並べて置くと、どちらの人も開けます。

## リンクが使われないとき

`git` か `source` があるリンクが次のどれかに当たると、リンクの値はどれも使われず、取得元が空の
追加画面が開きます。**エラーは表示されません。**

- 上の表にないパラメータがある。`utm_source` のような計測用のものや、変数の値を渡そうとする
  `var.<変数名>` も含みます
- 同じパラメータが 2 回ある
- `git` と `source` の両方がある
- `source` が `git::` で始まらない、`?` の後ろに `ref` 以外がある、`//` の後ろのフォルダが
  上の規則に合わない
- `ref` か `path` を、`source` の中と外の両方に書いている
- 値が空（`ref=` など）か、値の前後に空白がある
- `git` の URL が `https://` で始まらない、ユーザー名やパスワードを含む、`?` 以降の query か
  `#` 以降の fragment を含む
- `path` や `sourcePath` の書き方が上の規則に合わない
- `name` が 96 文字を超える、`ref` が 512 文字を超える
- `product` と `return_uri` の片方だけがある、または
  [App Handoff](../reference/app-handoff.md#product-key-と-return-uri-の規則) の規則に合わない

`git` も `source` も無いリンクは、取得元を入れた追加画面ではなく、ストアの一覧を開きます。

`web+takosumi:install` のリンクでは、規則に合わない値のうち次のものだけが、`/install` と同じく取得元が
空の追加画面になります。それ以外（知らないパラメータ、空の値、`path` の書き方など）では、
何も入っていないストアの一覧が開きます。デコードした長さが 4,096 文字を超えるリンクも同じです。

- `git` の URL の条件（`https://`、ユーザー名やパスワード、query、fragment）に合わない
- `source` の中身が規則に合わない
- `ref` か `path` を、`source` の中と外の両方に書いている
- `name` が 96 文字を超える、`ref` が 512 文字を超える

## 配る前に確かめる

自分でリンクを開き、追加画面の最初の画面の **取得元** に、リポジトリ、バージョン、フォルダが
表示されることを確かめます。Git URL などの値は、折りたたまれた **取得元の詳細** に入っています。
**取得元** が表示されず、**取得元の詳細** の入力欄が空なら、上のどれかに当たっています。
最初の画面は[クイックスタート](./quickstart.md#_6-サンプルを追加する)の画面と同じです。

## 開いた人に見えるもの

1. サインインしていない人には、サインインの画面に、追加するサービスの名前とバージョン、
   フォルダが表示されます。サインインすると追加画面に戻ります。
2. 追加画面の最初の画面に、サービス名、**取得元**、このあとの流れが表示されます。
3. **追加** を押すと、Takosumi は `ref` を commit に固定してリポジトリを調べます。そのあと
   **サービスを設定** で変数と接続を入れ、**追加前の確認** で内容を確かめてから追加します。

リンクの値はブラウザの履歴やログに残ります。リンクに秘密を入れないでください。
