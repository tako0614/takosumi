# 追加したサービスの更新・戻す・削除

ダッシュボードで追加したアプリを開きます。同じページに **版**、**設定**、**履歴**、
所有者向けの **アンインストール** があります。

更新・設定変更・前の版に戻す操作は、まず変更の確認（plan）を作ります。
作成・変更・削除されるものと料金の目安を確かめ、**許可して更新** または **許可して適用**
を押すまでクラウドへの変更は適用されません。ページを開き直しても、許可したことにはなりません。
削除の予約と取り消し、自動更新のオンとオフは、それぞれの操作で反映されます。

## 新しい版に更新する

**版** で **更新** を押します。新しい版をまだ検出していない場合は **新しい版を確認** で、
追跡中のブランチやタグの最新の内容を確認できます。どちらも変更内容の表示で止まります。
内容を確かめて **許可して更新** を押すと適用を始めます。

削除・作り直しを含む変更では追加の確認欄があり、承認が必要な計画では **この変更を承認**
も必要です。承認やポリシー・料金の条件で止まっている間は、適用できません。

Git の新しい commit の検出は、Cloudflare 構成では毎時の確認か Source webhookで行います。
Bun と PostgreSQL の標準構成には、この定期確認も webhookもありません。
commitを指定したアプリには新しいcommitが現れず、タグも別のcommitへ付け直されない限り変わりません。
別のブランチ、タグ、commitへ切り替えるときは、**版を指定** の **tag・branch・commit** に
入力して **内容を確認** を押します。ここでも許可するまで適用しません。

設定値や接続を変えるときは、**設定** の値や **使う接続** を変更して **内容を確認** を押します。
変更内容を確かめて **許可して適用** を押すまで、今の設定で動き続けます。

### 自動で更新する

**版** の **自動更新** で **新しい版が見つかったら自動で更新する** をオンにすると、
Takosumiが新しいcommitを見つけるたびに、更新用のplanを1回作ります。
自動で適用まで進むのは、削除・作り直しがなく、承認・ポリシー・料金の条件にかからず、
変わるリソースの一覧が分かっている変更だけです。それ以外は人の確認を待ちます。
止まったり失敗したりしても、同じcommitで自動ではやり直しません。既定はオフです
（[Source と Capsule](../concepts/sources.md)）。手動の **更新** ボタンは、この自動更新とは別です。

## 失敗したとき

アプリページの **要対応** に問題が表示されます。**理由とログを見る**、または **履歴** の
**詳細** から、その実行の結果・理由・ログを確認できます。

1. 接続の問題なら **設定** の **使う接続** を、moduleの問題ならGitリポジトリを直します。
2. **もう一度確認** で新しいplanを作り、内容を見てから許可します。
   **今の版で確認し直す** と表示される場合は、失敗した変更の再試行ではなく、今の版を現在の設定で確認します。

適用の応答が失われると、実行結果を確認できないと表示されます。この場合は繰り返し適用せず、
**履歴** からRunの結果と現在の状態を読み直します。失敗したRunでも、クラウド側への変更や
新しいStateVersionが残ることがあります。[実行モデル](../concepts/run-model.md#失敗したとき)を参照してください。
サーバー自体が動かない、runnerに届かない場合は、運用する人向けの
[トラブルシューティング](../self-host/troubleshooting.md)も参照できます。

## 前の版に戻す（ロールバック）

**版** の **前の版に戻す** に以前に適用した版が並びます。対象の **この版に戻す** を押すと、
その版の取得元（commit）を使うplanが作られます。内容を確かめて **許可して適用** を押して初めて戻ります。

戻す前に知っておくこと:

- 戻した結果は、新しいStateVersionとして履歴に積まれます。履歴を巻き戻したり消したりしません。
- 前の版の取得元を使って変更する操作です。データベースのレコードや保存したファイルは復元しません。
  planに削除・作り直しがあれば、中のデータを失う可能性があります。
- 設定値と接続は戻りません。planには現在の設定値と接続を使います。
- 戻す先のcommitがリポジトリに残っている必要があります。無いとplanが失敗します。

詳しくは[状態と出力](../concepts/state-and-outputs.md)を参照してください。

## 削除する

所有者は **アンインストール** から削除できます。ほかのアプリが使っている場合は、
影響する連携先が表示されます。削除はこのアプリがクラウド側に作ったリソースを取り除き、
その中のデータも失われる可能性があります。

- **猶予期間がある場合:** **アンインストール** と確認ダイアログで予約します。
  OSSの既定は7日で、運用する人が変更できます。猶予中はアプリとデータが残り、課金も続きます。
  **アンインストールを取り消す** で取り消せます。期限が来ると書き出しを試みてから削除します。
  書き出しの失敗だけでは削除は止まりませんが、予約した人の権限、書き出しの不明な結果、
  削除のplanやapplyを安全に確認できない場合は止まります
  （[削除の予約](../concepts/scheduled-uninstall.md)）。
- **今すぐ削除する場合:** **今すぐアンインストール** は削除のplanを開きます。
  書き出しは行いません。必要な承認と確認欄を通り、**許可してアンインストール** を押すと削除を始めます。
  猶予の無い環境や、予約済みのアプリで表示される操作です。元に戻せません。

まだ一度も適用していないアプリでは、**アンインストール** の確認後、その場で取り除きます。
クラウドに作ったものがあるか不明な場合は、先に実行結果と現在の状態を確かめてください。
