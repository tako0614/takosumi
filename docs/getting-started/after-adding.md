# 追加したサービスの更新・戻す・削除

追加したサービス（アプリ）は、dashboard の **ワークロード** から開きます。サービスの画面には
**概要**、**更新**、**設定** の 3 つのタブがあります。このページでは、追加したあとによく使う
操作を、画面の名前のとおりに説明します。

どの操作も、まず変更の確認（plan）を作り、作成・変更・削除されるリソースの数を見てから
デプロイ（apply）します。確認を作っただけでは何も変わりません。

## 新しい版に更新する

追跡している Git の ref に新しい commit が入ると、サービスの状態が **更新があります** になり、
画面の上に **更新する** が表示されます。

- **更新する** を押すと、変更の確認を作ります。承認が要らず、既存リソースの削除や置き換えを
  含まず、ポリシーや料金の条件で止められない変更なら、そのままデプロイまで進みます。それ以外は
  実行の画面で止まります。
- 内容を見てから進める場合は、**更新** タブの **サービスを更新** で **変更を確認** を押します。
  実行の画面で内容を確かめてから **デプロイを実行** を押します。

実行の画面では、承認が必要な変更に **この変更を承認** が、既存リソースの置き換えや削除を含む
変更に **破壊的な変更を承知のうえで実行** が表示されます。どちらも内容を確かめてから押します。

別のブランチ、タグ、commit に切り替えるときは、**更新** タブの **取得元のバージョン** で
**バージョンを変更** を開き、**ブランチ・タグ・コミット** に入れて **このバージョンを確認** を
押します。同じように変更の確認が作られます。

入力した設定値や接続を変えるときは、**設定** タブの **設定値** と **接続済みアカウント** で
変更し、**変更を確認** を押します。設定の画面ではまだ適用されません。

### 自動で更新する

**設定** タブの **自動更新** で **自動更新をオンにする** を押すと、新しい commit が見つかる
たびに 1 回、更新用の変更の確認を作ります。自動でデプロイまで進むのは、削除や置き換えがなく、
承認やポリシーの条件にかからず、変わるリソースの一覧が分かっている変更だけです。それ以外は
実行の画面で止まり、人が確かめるまでデプロイされません。既定はオフです
（[Source と Capsule](../concepts/sources.md)）。

## 失敗したとき

変更の確認（plan）やデプロイ（apply）が失敗すると、実行の画面に「〜に失敗しました。」と表示されます。
その下の **診断** に、エラーと警告や、接続の確認が必要かどうかが表示されます。

1. **診断** の内容に合わせて直します。接続の問題なら **設定** タブの **接続済みアカウント** を、
   module の問題なら Git のリポジトリを直します。
2. 実行の画面の **もう一度変更を確認** で、変更の確認を作り直します。

これまでの実行は、右上の頭文字のアイコン（ユーザーメニュー）にある **デプロイ履歴** に
新しい順に並びます。サーバー自体が動かない、runner に届かないなど、運用している人の側の
問題は[トラブルシューティング](../self-host/troubleshooting.md)を参照してください。

## 前の版に戻す（ロールバック）

**更新** タブの **更新履歴** に、デプロイした版が日時つきで並び、使われている版に **現在** と
表示されます。前の版の **以前の状態に戻す** を開いて **この状態に戻す** を押すと、その版の
取得元に戻す変更の確認が作られます。内容を確かめてデプロイしたときに初めて戻ります。

戻す前に知っておくこと:

- 戻した結果は新しい版として履歴に積まれます。履歴は消えないので、戻したあとで元に戻す
  こともできます。
- 戻るのは Takosumi が管理している状態です。データベースのレコードや保存したファイルなど、
  リソースの中身は戻りません。
- 戻す先の commit がリポジトリに残っている必要があります。無いと変更の確認が失敗します。
- 認証情報は版に含まれないため、戻しても今の接続が使われます。

詳しくは[状態と出力](../concepts/state-and-outputs.md)を参照してください。

## 削除する

**設定** タブの **サービスを削除** を開くと、2 つの方法があります。どちらも、このサービスが
クラウド側に作ったリソースを削除します。リソースの中のデータも消えます。

- **削除を予約** — **削除を予約する** を押すと、状態が **削除予定** になり、猶予期間（OSS の
  既定は 7 日）のあいだサービスとデータは残ります。そのあいだは **削除を取り消す** で取り消せ
  ます。期限が来ると、データの書き出しを試みてから削除します
  （[削除の予約](../concepts/scheduled-uninstall.md)）。
- **今すぐ完全に削除** — **削除の確認を開く** を押すと、削除の変更の確認が作られます。
  実行の画面で内容を確かめて実行すると、すぐに削除され、元に戻せません。まだ一度も
  デプロイしていないサービスは、この場で削除されます。

ほかのサービスから使われているサービスでは、削除の前に影響する連携サービスが表示されます。
