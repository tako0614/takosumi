# 追加したサービスの更新・戻す・削除

追加したサービスは、dashboard の **ワークロード** から開きます。サービスの画面には
**概要**、**更新**、**設定** の 3 つのタブがあります。このページでは、追加したあとによく使う
操作を、画面の名前のとおりに説明します。

削除の予約と取り消し、自動更新のオンとオフは、押したときにすぐ反映されます。それ以外の操作は、
まず変更の確認（plan）を作り、作成・変更・削除されるリソースの数を見てからデプロイ（apply）
します。変更の確認を作っただけでは何も変わりません。

## 新しい版に更新する

追跡しているブランチに新しい commit が入ったことを Takosumi が見つけると（定期の確認か、Source の
webhook で見つけます。Cloudflare 構成の定期の確認は毎時です）、サービスの状態が
**更新があります** になり、画面の上に **更新する** が表示されます。commit を指定して追加した
サービスは、Git の変更では **更新があります** になりません。タグを指定した場合も、そのタグを
別の commit に付け直さない限りなりません。新しい版へは、下の **バージョンを変更** で切り替えます。
どの指定でも、依存している別のサービスの Output が変わると **更新があります** になります
（[値を別の Capsule に渡す](../concepts/state-and-outputs.md#値を別の-capsule-に渡す)）。

- **更新する** を押すと、変更の確認を作ります。承認が要らず、既存リソースの削除や置き換えを
  含まず、ポリシーや料金の条件で止められない変更なら、そのままデプロイまで進みます。
  それ以外は、実行の画面で止まります。
- 内容を見てから進める場合は、**更新** タブの **サービスを更新** で **変更を確認** を押します。
  実行の画面で内容を確かめてから、**デプロイを実行** を押します。

既存リソースの削除や置き換えを含む変更は、承認が要ります。実行の画面でまず
**この変更を承認** を押すと、**デプロイを実行** の代わりに **破壊的な変更を承知のうえで実行**
が表示されます。どちらも、内容を確かめてから押します。

別のブランチ、タグ、commit に切り替えるときは、**更新** タブの **取得元のバージョン** で
**バージョンを変更** を開き、**ブランチ・タグ・コミット** に入れて **このバージョンを確認** を
押します。同じように変更の確認が作られます。

入力した設定値や接続を変えるときは、**設定** タブの **設定値** と **接続済みアカウント** で
変更し、**変更を確認** を押します。設定の画面では、まだ適用されません。

### 自動で更新する

**設定** タブの **自動更新** を開いて **自動更新をオンにする** を押すと、Takosumi が新しい
commit を見つけるたびに、更新用の変更の確認を 1 回作ります。自動でデプロイまで進むのは、
削除や置き換えがなく、承認やポリシーの条件にかからず、変わるリソースの一覧が分かっている
変更だけです。それ以外は実行の画面で止まり、人が確かめるまでデプロイされません。止まったり
失敗したりしても、同じ commit で自動ではやり直しません。既定はオフです
（[Source と Capsule](../concepts/sources.md)）。

## 失敗したとき

変更の確認（plan）やデプロイ（apply）が失敗すると、実行の画面に「〜に失敗しました。」と
表示されます。原因の手がかりがある場合は、その下の **診断** に、エラーと警告や、接続の確認が
必要かどうかが表示されます。

1. **診断** の内容に合わせて直します。接続の問題なら **設定** タブの **接続済みアカウント** を、
   module の問題なら Git のリポジトリを直します。
2. 実行の画面の **もう一度変更を確認** で、変更の確認を作り直します。

これまでの実行は、右上の頭文字のアイコン（ユーザーメニュー）にある **デプロイ履歴** に
新しい順に並びます。サーバー自体が動かない、runner に届かないなど、運用している人の側の
問題は[トラブルシューティング](../self-host/troubleshooting.md)を参照してください。

## 前の版に戻す（ロールバック）

**更新** タブの **更新履歴** を開くと、デプロイした版が日時つきで並び、使われている版に
**現在** と表示されます。前の版の **以前の状態に戻す** を開いて **この状態に戻す** を押すと、
その版の取得元（commit）に戻す変更の確認が作られます。内容を確かめてデプロイしたときに
初めて戻ります。

戻す前に知っておくこと:

- 戻した結果は、新しい版として履歴に積まれます。履歴は消えないので、戻したあとで元に戻す
  こともできます。
- 戻るのは取得元と、Takosumi が管理している状態です。データベースのレコードや保存した
  ファイルなど、リソースの中身は戻りません。
- 設定値と接続は戻りません。戻す変更の確認には、今の設定値と接続が使われます。
- 戻す先の commit がリポジトリに残っている必要があります。無いと変更の確認が失敗します。

詳しくは[状態と出力](../concepts/state-and-outputs.md)を参照してください。

## 削除する

**設定** タブの **サービスを削除** を開くと、2 つの方法があります。どちらも、このサービスが
クラウド側に作ったリソースを削除します。リソースの中のデータも消えます。ほかのサービスから
使われているサービスでは、影響する連携サービスがここに表示されます。

- **削除を予約** — **削除を予約する** を押すと、状態がすぐに **削除予定** になります。猶予期間
  （OSS の既定は 7 日で、運用している人が変えられます）のあいだはサービスとデータが残り、
  課金も続きます。そのあいだは **削除を取り消す** で取り消せます。期限が来ると、データの
  書き出しを試みてから削除します。書き出しに失敗しても、削除は進みます。ただし、安全に続けられない
  ときは止まります。たとえば、予約した人の権限を期限に確かめられない、書き出しが途中で
  中断されて結果を確かめられない、削除の変更の確認やデプロイが失敗したり拒否されたりした、
  などの場合です。止まると、画面に取り消すか今すぐ削除するよう表示されます
  （[削除の予約](../concepts/scheduled-uninstall.md)）。
- **今すぐ完全に削除** — **削除の確認を開く** を押すと、削除の変更の確認が作られます。
  データの書き出しは行いません。実行の画面で **この変更を承認** を押し、
  「この削除を実行しますか？」で承認してから **破壊的な変更を承知のうえで実行** を押すと、
  すぐに削除され、元に戻せません。

まだ一度もデプロイしていないサービスでは、カードの名前が **サービスを削除** になり、
**削除の確認を開く** のあと「このサービスを削除しますか？」で確かめると、その場で削除
されます。
